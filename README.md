# org_chart_mtp — Оргструктура компании для Frappe/HRMS

Интерактивная страница оргчарта для Frappe Desk (v16): дерево отделов
с плитками, боковой панелью, целями из HRMS, поиском, экспортом и правами
видимости по должностям — без единой кастомной роли.

Приложение извлечено из кастомной страницы HRMS и оформлено как отдельный
Custom App: ставится через `bench get-app`, все поля и настройки
разворачиваются миграцией автоматически.

---

## Возможности

**Оргчарт** (`/desk/org_chart_mtp`)

- рекурсивная иерархия любой глубины; группы (департаменты) идут
  горизонтальным рядом, службы — вертикальной цепочкой;
- зум к курсору колесом мыши, панорамирование перетаскиванием
  (pointer events: мышь и тач единообразно; зажатие на плитке = пан,
  короткий клик = открытие), кнопки масштаба и сброс;
- **поиск** по отделам и сотрудникам с автоскроллом к найденному узлу
  и подсветкой;
- **мультикомпанийность**: селектор в шапке фильтрует дерево, чипы и
  поиск по `Department.company` / `Employee.company` (предки выбранной
  компании всегда видны — дерево не теряет связности). При одной
  компании селектор скрыт; выбор запоминается в браузере;
- **deep links**: открытый отдел/сотрудник пишется в URL-hash
  (`#dept=…` / `#emp=…`) — ссылкой можно поделиться; кнопка «Назад»
  браузера закрывает панель;
- **realtime-обновления**: при изменении Department / Employee / Goal /
  File / настроек (doc_events) открытые страницы мягко перезагружают
  данные (debounce ~1,5 с; зум, пан, свёрнутость и открытая панель
  сохраняются);
- сворачивание/разворачивание подотделов;
- плитка отдела показывает **ЦКП по умолчанию** или **Функции** —
  переключается пользователем, выбор запоминается;
- боковая панель отдела показывает **Функции по умолчанию** или **ЦКП** —
  тоже переключается;
- цвет плитки берётся **только из поля Department.custom_color (hex)**;
  если поле пусто — нейтральный серо-синий `#475569`. Значение
  валидируется на сервере (`#RRGGBB`, иначе сохранение не пройдёт);
- чипы сотрудников на плитках (отключается в настройках), клик —
  панель сотрудника: контакты, вложения, цели;
- вкладки панели отдела: **Папка** (внешняя папка + вложения), **Wiki**,
  **Цели**.

**Цели — обычные Goal из HRMS**

- цели отдела — Goal с заполненным полем «Отдел»
  (`Goal.custom_department`, создаётся миграцией): статус, владелец,
  срок, прогресс; каждая цель — ссылка на документ;
- **«+ Добавить цель»** в панели отдела и в панели сотрудника — диалог
  создаёт Goal прямо из оргчарта;
- права на создание (проверяются **на сервере**): только HR или
  вышестоящий начальник — рядовой сотрудник не может назначить цель ни
  себе, ни другим; цель отдела может создать HR или руководитель ветки,
  которой принадлежит отдел.

**Экспорт** (одна кнопка → диалог)

- **PNG / JPG** — растровые, рендер в браузере; разрешение 1×–4×
  (итоговый размер в пикселях показывается живьём), качество JPG
  85/92/96 %;
- **PDF — векторный, текст выделяется и копируется**: HTML схемы
  отправляется на сервер и рендерится headless-Chromium (штатный
  генератор frappe v16, `bench setup-chromium`); откат на wkhtmltopdf,
  затем — на растровый PDF клиента;
- на векторный PDF действует **per-user rate limit** (по умолчанию 8
  рендеров за скользящую минуту) — Chromium на сервере дорогой, защита
  от зажатой кнопки и злонамеренного спама; лимит настраивается
  константой `EXPORT_RATE_LIMIT` в `api/export.py`.

**Права видимости — по должностям, а не по ролям страницы**

| Кто | Структура, ЦКП, функции, контакты | Личные цели | Цели отделов | Создание целей |
|---|---|---|---|---|
| HR (должность из настроек или роль HR Manager / System Manager) | все | все | все | всем |
| Руководитель (есть подчинённые по `reports_to`) | все | своя ветка | отделы своей ветки | подчинённым и своим отделам |
| Рядовой сотрудник | все | только свои | скрыты | нельзя |

Всё отсечение делается на сервере: цели, недоступные пользователю, не
попадают в браузер вовсе (не «прячутся в интерфейсе»).

**Desk-интеграция (v16)**

- карточка «Оргструктура» на домашнем экране (`add_to_apps_screen`);
- собственный док (рельса слева) с модулем Org Chart;
- сайдбар модуля: страница оргчарта, справочники «Отделы», «ЦКП (KRA)»,
  «Настройки оргчарта».

## Установка

> Приложение требует **frappe/erpnext/hrms v16** (`required_apps = ["hrms"]`).

```bash
cd frappe-bench
bench get-app https://github.com/MTPplus/org_chart --branch main
bench --site <site> install-app org_chart_mtp
bench --site <site> migrate
bench build
```

Репозиторий называется `org_chart`, а приложение — `org_chart_mtp`:
`bench get-app` читает имя из `pyproject.toml` и сам переименовывает папку
`apps/org_chart` → `apps/org_chart_mtp`, ничего дополнительно делать не нужно.

Для векторного PDF-экспорта включите серверный рендер (один раз):

```bash
bench setup-chromium   # скачает Chromium и пропишет chromium_path
```

Частная сборка из приватного зеркала (например Gitea):

```bash
bench get-app https://<user>:<PAT>@git.example.com/MTPplus/org_chart.git
```

## Что делает установка (миграцией, автоматически)

Кастомные поля создаются хуками `after_install` / `after_migrate` через
`create_custom_fields`:

| DocType | Поле | Тип | Назначение |
|---|---|---|---|
| Department | `custom_color` | Data | hex-цвет плитки (`#2563eb`), валидируется |
| Department | `custom_functions` | Small Text | функции отдела, по строке |
| Department | `custom_kra` | Link → KRA | ЦКП отдела |
| Department | `custom_wiki_url` | Data | ссылка на wiki |
| Department | `custom_folder_url` | Data | ссылка на внешнюю папку |
| Goal | `custom_department` | Link → Department | цель относится к отделу |

Также создаётся Single-doctype **Org Chart Settings** с дефолтами:

- `card_default` = **ЦКП** — что на плитке;
- `panel_default` = **Функции** — что в боковой панели;
- `show_employees` = включено;
- `hr_designations` — список должностей с полным доступом
  (по умолчанию: HR Manager, HR Business Partner, HR-директор,
  Директор по персоналу; роли HR Manager и System Manager дают полный
  доступ всегда).

Хуки `doc_events` (Department / Employee / Goal / File / настройки):
инвалидация Redis-кэша `get_org_data` + realtime-рассылка открытых
оргчартов; `validate` Department проверяет hex-формат цвета.

При `bench --site <site> uninstall-app org_chart_mtp` созданные
Custom Field удаляются (значения полей будут потеряны).

## Настройка

1. Откройте **Org Chart Settings** (сайдбар модуля Org Chart или поиск).
2. При необходимости поменяйте содержимое плитки/панели по умолчанию
   и список HR-должностей.
3. В каждом Department заполните секцию **«Оргструктура (org_chart_mtp)»**:
   цвет, функции, ЦКП, ссылки.
4. Пользователи переключают содержимое плитки/панели кнопками в шапке
   страницы — выбор хранится в их браузере и перекрывает дефолты.

## Демо-данные (плейсхолдеры)

На тестовом сайте можно развернуть плейсхолдерный набор: 13 отделов,
16 сотрудников с иерархией `reports_to`, 15 целей (личные и отделские),
продуманная палитра hex-цветов, ЦКП и wiki-ссылки:

```bash
bench --site <site> execute org_chart_mtp.demo.make_demo_data
```

Вторая компания для демонстрации мультикомпанийности (отдельная ветка
отделов + сотрудники + цели):

```bash
bench --site <site> execute org_chart_mtp.demo.make_demo_company2
```

Повторные запуски безвредны (пропускаются, если данные уже есть).

## Тесты

### Лёгкие CI-тесты (без установки bench)

В репозитории есть `ci_tests/` — ручные статические проверки, которые
прогоняет GitHub Actions на каждый push/PR (без развёртывания
frappe/bench — сознательно, полная развёртка в CI признана
ресурсоёмкой):

```bash
python ci_tests/check_py_compile.py    # компиляция всех .py
python ci_tests/check_json_valid.py    # валидность всех .json
python ci_tests/check_js_syntax.py     # node --check всех .js
python -m unittest discover -s ci_tests -p "test_*.py" -v
```

### Полные интеграционные тесты (требуют bench+site)

```bash
bench --site <site> set-config allow_tests true
bench --site <site> run-tests --app org_chart_mtp
```

Покрывается (35 тестов):

- создание кастомных полей (и идемпотентность повторной миграции);
- настройки: дефолты «плитка = ЦКП, панель = Функции», парсинг
  HR-должностей, запрет произвольных значений;
- **скоупы**: HR через должность и через нативную роль; руководитель
  видит свою ветку (`reports_to`); рядовой сотрудник — только свои цели;
  цели отделов скрыты от рядовых; структура публична для всех; отсечение
  недоступных целей — на сервере;
- **создание целей**: HR — кому угодно; руководитель — подчинённым и в
  отделы своей ветки; рядовой — не может ни себе, ни другим (PermissionError);
  мультикомпанийные поля в ответе API (`companies`, `company` у
  сотрудников, `goal_editable_depts`);
- hex-валидация `Department.custom_color` (валидный нормализуется,
  пустой разрешён, битый — `ValidationError`);
- ограничения `get_employee_details`.

## Структура приложения

```
org_chart_mtp/
├── hooks.py                     # required_apps, doc_events, install-хуки
├── install.py                   # create_custom_fields + дефолты настроек
├── uninstall.py                 # очистка кастомных полей
├── demo.py                      # демо-данные (+ вторая компания)
├── api/permission.py            # доступ к карточке приложения
├── api/events.py                # doc_events: кэш, realtime, hex-валидация
├── api/export.py                # векторный PDF (Chromium/wkhtmltopdf + rate limit)
├── dock/org_chart_mtp/….json    # док (рельса Desk) — v16
├── org_chart/                   # модуль Org Chart
│   ├── sidebar/org-chart/….json # сайдбар модуля — v16
│   ├── doctype/org_chart_settings/
│   └── page/org_chart_mtp/       # страница: .js / .py / .json
├── public/icons/module-icons.svg
├── public/images/org-chart-mtp-logo.svg
└── tests/                        # test_custom_fields / test_settings /
                                 # test_scopes / test_goals_and_validation
```

В корне репозитория рядом с приложением лежит `ci_tests/` — лёгкие
статические тесты для GitHub Actions (см. раздел «Тесты»).
