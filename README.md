# org_chart_mtp — Оргструктура компании для Frappe/HRMS

Интерактивная страница оргчарта для Frappe Desk (v16): дерево отделов
с плитками, боковой панелью, целями, метриками и правами видимости по
должностям — без единой кастомной роли.

Приложение извлечено из кастомной страницы HRMS и оформлено как отдельный
Custom App: ставится через `bench get-app`, все поля и настройки
разворачиваются миграцией автоматически.

---

## Возможности

**Оргчарт** (`/desk/org_chart_mtp`)

- рекурсивная иерархия любой глубины; группы (департаменты) идут
  горизонтальным рядом, службы — вертикальной цепочкой;
- зум к курсору колесом мыши, панорамирование перетаскиванием,
  кнопки масштаба и сброс;
- сворачивание/разворачивание подотделов;
- плитка отдела показывает **ЦКП по умолчанию** или **Функции** —
  переключается пользователем, выбор запоминается;
- боковая панель отдела показывает **Функции по умолчанию** или **ЦКП** —
  тоже переключается;
- цвет плитки берётся **только из поля Department.custom_color (hex)**;
  если поле пусто — нейтральный серо-синий `#475569`;
- чипы сотрудников на плитках (отключается в настройках), клик —
  панель сотрудника: контакты, вложения, цели;
- вкладки панели отдела: **Папка** (внешняя папка + вложения), **Wiki**,
  **Цели и метрики** (цели отдела + метрики в JSON).

**Права видимости — по должностям, а не по ролям страницы**

| Кто | Структура, ЦКП, функции, контакты | Личные цели | Цели отделов, метрики |
|---|---|---|---|
| HR (должность из настроек или роль HR Manager / System Manager) | все | все | все |
| Руководитель (есть подчинённые по `reports_to`) | все | своя ветка | отделы своей ветки |
| Рядовой сотрудник | все | только свои | скрыты |

То есть «HR видит цели всех» и «Директор видит свою ветку» — разные скоупы.

**Desk-интеграция (v16)**

- карточка «Оргструктура» на домашнем экране (`add_to_apps_screen`);
- собственный док (рельса слева) с модулем Org Chart;
- сайдбар модуля: страница оргчарта, справочники «Отделы», «ЦКП (KRA)»,
  «Настройки оргчарта».

## Установка

> Приложение требует **frappe/erpnext/hrms v16** (`required_apps = ["hrms"]`).

```bash
cd frappe-bench
bench get-app https://github.com/MTPplus/org_chart --branch main
bench --site <site> install-app org_chart_mtp
bench --site <site> migrate
bench build
```

Репозиторий называется `org_chart`, а приложение — `org_chart_mtp`:
`bench get-app` читает имя из `pyproject.toml` и сам переименовывает папку
`apps/org_chart` → `apps/org_chart_mtp`, ничего дополнительно делать не нужно.

Частная сборка из приватного зеркала (например Gitea):

```bash
bench get-app https://<user>:<PAT>@git.example.com/MTPplus/org_chart.git
```

## Что делает установка (миграцией, автоматически)

Кастомные поля создаются хуками `after_install` / `after_migrate` через
`create_custom_fields`:

| DocType | Поле | Тип | Назначение |
|---|---|---|---|
| Department | `custom_color` | Data | hex-цвет плитки (`#2563eb`) |
| Department | `custom_functions` | Small Text | функции отдела, по строке |
| Department | `custom_kra` | Link → KRA | ЦКП отдела |
| Department | `custom_metrics` | JSON | метрики отдела |
| Department | `custom_wiki_url` | Data | ссылка на wiki |
| Department | `custom_folder_url` | Data | ссылка на внешнюю папку |
| Goal | `custom_department` | Link → Department | цель относится к отделу |

Также создаётся Single-doctype **Org Chart Settings** с дефолтами:

- `card_default` = **ЦКП** — что на плитке;
- `panel_default` = **Функции** — что в боковой панели;
- `show_employees` = включено;
- `hr_designations` — список должностей с полным доступом
  (по умолчанию: HR Manager, HR Business Partner, HR-директор,
  Директор по персоналу; роли HR Manager и System Manager дают полный
  доступ всегда).

При `bench --site <site> uninstall-app org_chart_mtp` созданные
Custom Field удаляются (значения полей будут потеряны).

## Настройка

1. Откройте **Org Chart Settings** (сайдбар модуля Org Chart или поиск).
2. При необходимости поменяйте содержимое плитки/панели по умолчанию
   и список HR-должностей.
3. В каждом Department заполните секцию **«Оргструктура (org_chart_mtp)»**:
   цвет, функции, ЦКП, метрики, ссылки.
4. Пользователи переключают содержимое плитки/панели кнопками в шапке
   страницы — выбор хранится в их браузере и перекрывает дефолты.

## Тесты

### Лёгкие CI-тесты (без установки bench)

В репозитории есть `ci_tests/` — ручные статические проверки, которые
прогоняет GitHub Actions на каждый push/PR (без развёртывания
frappe/bench — сознательно, полная развёртка в CI признана
ресурсоёмкой):

```bash
python ci_tests/check_py_compile.py    # компиляция всех .py
python ci_tests/check_json_valid.py    # валидность всех .json
python ci_tests/check_js_syntax.py     # node --check всех .js
python -m unittest discover -s ci_tests -p "test_*.py" -v
```

Юнит-тесты (25 шт.) проверяют: структуру hooks и кастомных полей,
форматы patches.txt/page JSON, рекурсию `reports_to`, правило
«ЦКП — всем, метрики — по праву» на уровне чистых функций.

### Полные интеграционные тесты (требуют bench+site)

```bash
bench --site <site> set-config allow_tests true
bench --site <site> run-tests --app org_chart_mtp
```

Покрывается:

- создание кастомных полей (и идемпотентность повторной миграции);
- настройки: дефолты «плитка = ЦКП, панель = Функции», парсинг
  HR-должностей, запрет произвольных значений;
- **скоупы**: HR через должность и через нативную роль; руководитель
  видит свою ветку (`reports_to`); рядовой сотрудник — только свои цели;
  цели отделов скрыты от рядовых; структура публична для всех;
  **ЦКП отделов виден всем пользователям, метрики — только HR и
  руководителям (в рамках их ветки), причём метрики вырезаются
  на сервере, не доходя до браузера без права**;
- цвет приходит из `Department.custom_color`, при отсутствии — нейтральный;
- обогащение ЦКП из KRA; ограничения `get_employee_details`.
